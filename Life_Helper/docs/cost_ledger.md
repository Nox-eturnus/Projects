it becomes a billing problem — see Part I2.

## Notes

- The GitHub Actions workflow (`.github/workflows/life-helper-verify.yml`)
  is scoped to `Life_Helper/**` via a `paths` filter so unrelated changes
  elsewhere in this monorepo don't burn Actions minutes.
- **Part C3 (2026-09-11):** the Google Cloud blocker in the Account
  confirmations table was re-examined.
  OAuth-client setup guides (for example gmailr's,
  https://gmailr.r-lib.org/articles/oauth-client.html) state that billing
  isn't required to configure a consent screen or create an OAuth client; the card prompt
  hit in Part A1 was most likely the _free trial_ signup, a separate flow
  (not confirmed until the retry). The
  C3 runbook creates the project from `console.cloud.google.com/projectcreate`
  without starting a trial. If a card is demanded anyway, Decision 12's
  fallback applies (C3 ships without calendar data) — record it here.
- **Part C3 retry (2026-10-01 → 2026-10-02): confirmed — no card.** The
  project, Calendar API, consent screen, and Desktop OAuth client were all
  created without a billing account or a trial, so Decision 12's fallback
  wasn't needed. Publishing to "In production" (to avoid Testing mode's
  7-day refresh-token expiry) required a homepage and privacy policy URL;
  both are on the existing Pages site (`/privacy`), so no new component.
  The app stays unverified, which is free and fine for a single user.
- The Google Cloud blocker was the first apparent deviation from Decision
  11's "no card on file anywhere" rule. It turned out not to be one: the
  card belonged to the free-trial flow, which C3 avoided.
- Rows that still say "not yet" or "not built" are expected at this point —
  they belong to phases that haven't started. Populate them as each phase
  builds the component and measures it against its dashboard.
